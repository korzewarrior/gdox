# SP80NB80 RF02 evidence

This record defines the evidence boundary for the experimental
`HL-DT-ST DVDRAM SP80NB80 RF02` interface added in GDOX 0.2.3.

## observed hardware

- USB identity `0e8d:1887`, device revision `0000`;
- SCSI identity `HL-DT-ST`, `DVDRAM SP80NB80`, revision `RF02`;
- Ubuntu host using the Linux USB Bulk-Only Transport diagnostic endpoint;
- media ready with `READ CAPACITY(10)` last LBA `6991` and 2,048-byte blocks;
- physical-format geometry `03 1A AF`.

Serial numbers, device paths, host identity, and disc data were not retained.

## read-only XDATA evidence

Nine read-only register reads returned the following values:

| address | value | role in the bounded profile |
|---|---:|---|
| `0x8538` | `03` | stock XGD1 capacity byte 0 |
| `0x8539` | `1B` | stock XGD1 capacity byte 1 |
| `0x853A` | `4F` | stock XGD1 capacity byte 2 |
| `0x8A37` | `00` | not used by this profile |
| `0x8A38` | `00` | not used by this profile |
| `0x8A39` | `00` | not used by this profile |
| `0x8BE2` | `03` | stock XGD1 geometry byte 0 |
| `0x8BE3` | `1A` | stock XGD1 geometry byte 1 |
| `0x8BE4` | `AF` | stock XGD1 geometry byte 2 |

This matches the GP63 RF02 XGD1 address layout and differs from the GP65 PB00
capacity layout. GDOX therefore selects it only after the complete USB and
SCSI identity matches, admits only XGD1 media, bounds reads to 32 sectors, and
uses manual eject.

## not yet validated

The diagnostic session was explicitly read-only. It did not perform a volatile
activation, expose the unlocked descriptor, stream Xbox sectors, launch xemu,
or verify restoration on this physical drive. Release and website wording must
keep the interface experimental until one complete live cycle confirms all of
those steps. The transaction rejects values outside the known XGD1
stock/live/transition set, and a USB power cycle independently clears volatile
controller state.
